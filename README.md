# La Casa Vella

Web de La Casa Vella, casa de poble familiar al Bedorc (1898): allotjaments, restaurant, història, entorn i contacte.

## Estructura

| Ruta | Què és |
| --- | --- |
| `index.html` | Versió de treball. Conté tota la pàgina (HTML, CSS i JavaScript) i les eines de revisió: el selector de propostes, la vista mòbil (tecla M) i la franja d'esborrany. |
| `build.py` | Genera la versió per al domini a `dist/`. |
| `dist/` | Versió per publicar: una pàgina per idioma (`index.html`, `es/`, `en/`) amb les etiquetes per a Google i xarxes i sense les eines de revisió, `robots.txt` i `sitemap.xml`. |
| `maite-app/` | Maite, el back office (React, Vite, HeroUI). Es construeix a `dist/maite/` (vegeu més avall). Com està fet i quines llibreries fa servir: `maite-app/README.md`. |
| `android/` | Maite per a Android: app nativa (Compose) amb tot el que fa la web, per instal·lar a mà (vegeu `android/README.md`). |
| `lib/` | Lògica compartida de les funcions: reserves i preus (`booking.js`), Maite (`maite.js`), contingut dels allotjaments (`stays.js`), taules del restaurant (`restaurant.js`) avisos a l'app d'Android (`push.js`), el pla d'Instagram (`plan.js`) i les stories amb l'enllaç (`igapp.js`). |
| `docs/social/` | L'equip de xarxes de Claude Code: el context de la casa, les regles i els informes de cada dilluns. Els agents són a `.claude/agents/social-*.md`, les skills a `.claude/skills/social-*/` i les dades de cada setmana les recull `social.py` (vegeu `docs/social/README.md`). |
| `cron/` | Un Worker de Cloudflare que cada 5 minuts publica els posts d'Instagram programats (vegeu `cron/README.md`). |
| `img/` | Fotos, logo, isotip i plaques dels allotjaments. |
| `fonts/` | Tipografies de marca: Le Monde Livre i Halyard Display. |

És HTML pla, sense framework ni dependències.

## Actualitzar la web

1. Edita `index.html`.
2. Regenera la versió publicable:

   ```bash
   npm install
   npm run build:site
   ```

   Fa `python3 build.py https://casavellarural.com` i després construeix Maite a `dist/maite/` (`npm run build` només refà Maite). L'URL és opcional. Serveix per a l'enllaç canònic i la imatge que es veu quan es comparteix la web.
3. Fes commit dels canvis, inclosa la carpeta `dist/`, i puja'ls.

## Idiomes

La web es veu en català, castellà o anglès, cada idioma a la seva adreça: `/` (català), `/es/` i `/en/`. `build.py` escriu les tres pàgines ja traduïdes, perquè Google i els assistents d'IA les llegeixin sense executar JavaScript. Qui obre `/` per primer cop va a l'idioma del navegador (el primer de català, castellà o anglès; si no n'hi ha cap, anglès); després, al de l'última pàgina que ha vist o al que ha triat amb el selector CA ES EN de la capçalera (al menú en mòbil). Ho fa `functions/_middleware.js` amb la galeta `lcv-lang`. Els enllaços antics amb `?lang=es` porten a `/es/`. Els rastrejadors, que no envien idioma, llegeixen cada pàgina on és. La versió de revisió (`index.html` sol) continua traduint al navegador i accepta `?lang=es`.

- `index.html` és escrit en català. El diccionari `I18N` (al principi del codi) té el castellà i l'anglès de cada text, amb el text català com a clau: si canvies o afegeixes un text a la pàgina, afegeix-hi l'entrada o sortirà en català.
- El text que genera el codi (calendari, preus, avisos, reserva) passa per `tr('català', 'castellano', 'English')`.
- Els textos dels allotjaments que es canvien a Maite només existeixen en català: en castellà i anglès la pàgina mostra els que té traduïts.
- Els correus a l'hoste (reserva confirmada o pendent i resposta al formulari de contacte) surten en l'idioma en què ha fet servir la web: la pàgina l'envia amb la reserva i el formulari, i es desa a Stripe. Els avisos a la Casa Vella són en català i diuen en quin idioma escriure a l'hoste. La vista prèvia de Maite (Correus) els mostra en català.

## Cercadors i assistents d'IA

`build.py` posa a cada pàgina el títol i la descripció del seu idioma, l'enllaç canònic, les alternatives d'idioma (`hreflang`) i les dades estructurades (JSON-LD: l'allotjament amb els quatre allotjaments, l'adreça, el telèfon, les hores d'entrada i sortida i els serveis, i el restaurant). També escriu `robots.txt` (tots els rastrejadors, els d'IA inclosos, poden llegir la web; `/api/` no) i `sitemap.xml`. `/llms.txt` és una funció (`functions/llms.txt.js`) amb els fets de la casa en text pla i els preus, les normes i els dies del restaurant que hi ha a Maite en aquell moment. No hi ha puntuació de Google a les dades estructurades: Google no accepta les que marca el mateix negoci. Després de cada publicació, `python3 indexnow.py` avisa Bing (el cercador de ChatGPT) per IndexNow; la clau és `INDEXNOW_KEY` a `build.py`. El pla de tot el que no es fa des del codi (Google Business Profile, Search Console, directoris…) és a `docs/seo.md`; els passos i els textos per donar-se d'alta, a `docs/fichas.md`, i les preguntes que se segueixen, a `docs/aeo.md`.

- **Opinions**: la secció d'opinions mostra la puntuació de Google i les ressenyes que Google posa primer (fins a cinc), en l'idioma de la pàgina, amb el nom de cada autor. Ho fa `functions/api/reviews.js` amb la Places API (New). Les condicions de Google no deixen guardar-les: la pàgina les demana quan s'hi arriba i el navegador les guarda una hora. Per activar-ho, a Google Cloud, projecte `casa-vella-booking` (el del compte de servei del calendari), amb la facturació activada: APIs & Services → Library → «Places API (New)» → Enable; després, Credentials → Create credentials → API key, restringida a «Places API (New)», i a Cloudflare Pages la variable `GOOGLE_PLACES_KEY` amb aquesta clau. Sense clau no es consulta res. Com que Google no deixa baixar la quota i el pressupost només avisa, la funció es limita a 30 consultes al dia i 900 al mes (per sota de les 1.000 gratuïtes), comptades pel Durable Object `PlacesBudget` del Worker de `cron/`, que atén una petició cada vegada, perquè visites simultànies no puguin passar el límit; es canvien amb les variables `PLACES_PER_DAY` i `PLACES_PER_MONTH`. Cal lligar-lo al projecte de Pages: Settings → Bindings → Durable Object, variable `PLACES_BUDGET`, Worker `casavella-cron`, classe `PlacesBudget`. Sense aquest lligam, encara que hi hagi clau, no es consulta res. Passat el límit, la secció mostra només els dos botons. `/api/reviews` diu què falta si no funciona. Mentre no funcioni, la secció mostra només els dos botons.
- **Correu per demanar l'opinió**: l'endemà que un hoste marxa, li arriba un correu en l'idioma de la reserva (les de Maite, en català) amb les gràcies i l'enllaç per escriure l'opinió a Google, i la possibilitat de respondre el correu si hi ha alguna cosa a millorar. Va a totes les reserves de la web i de Maite amb correu que no s'han cancel·lat: Google prohibeix demanar-la només a qui ha quedat content o donar res a canvi. Ho fa `lib/review-requests.js` un cop al dia a partir de les 11:00, cridat pel Worker de `cron/` i per `/api/settings` (que demana cada visita a la web), així que no depèn del Worker. Cada reserva que l'ha rebut queda marcada al seu esdeveniment del calendari (`review: sent`) i no el torna a rebre; si un dia no s'executa, l'endemà recull els que van marxar fins a tres dies abans. Cal `RESEND_API_KEY`. Per aturar-ho: variable `REVIEW_EMAILS` = `off`. Es pot veure a Maite, Correus.
- **Guies**: articles sobre l'entorn (Montserrat, les caves de Sant Sadurní, la temporada de calçots…), cadascun amb les seves fonts, a `/guies/`, `/es/guias/` i `/en/guides/`. Surten de `content/guides/*.json` i els escriu `guides.py` (des de `build.py`): una pàgina per idioma amb les dades estructurades d'article, l'índex de cada idioma, els enllaços a la secció de l'entorn de la portada i el sitemap. La rutina setmanal n'afegeix una cada dues setmanes i revisa les que hi ha.
- **Fitxa de Google (Google Business Profile)**: cada post del feed que Maite publica a Instagram surt també a la fitxa de Google, amb la primera imatge, el text sense telèfons ni etiquetes i el botó cap a la web («Reserva» si l'enllaç és de reserva). A Maite, al costat d'«Obre a Instagram», hi surt «Obre a Google», o per què Google no l'ha acceptat. A més, la rutina setmanal de SEO deixa la publicació de la setmana a `content/gbp/` i el cron la publica el dia que toca. Ho fa `lib/gbp.js` amb l'API de Business Profile. Cal una d'aquestes dues: `GBP_REFRESH_TOKEN`, `GBP_CLIENT_ID` i `GBP_CLIENT_SECRET` (un testimoni OAuth d'info@casavellarural.com amb l'àmbit `business.manage`) o `GBP_AS` (el correu que gestiona la fitxa, amb la delegació de domini del compte de servei per a aquest àmbit). La fitxa es troba sola (la que es diu La Casa Vella) o es fixa amb `GBP_LOCATION`. Per aturar-ho: `GBP_POSTS=off`.
- **Agenda**: «Què passa a prop», a la secció de l'entorn, surt de `content/agenda.json` (data, lloc, minuts en cotxe, text en tres idiomes i la font). `build.py` treu el que ja ha passat i, si no queda res, no mostra el bloc. La manté la rutina setmanal de Claude (`docs/seo-rutina.md`), que cada dilluns busca què hi ha a prop amb fonts oficials, revisa la web, mira si surt a les cerques i, si totes les comprovacions passen, ho integra sola a `main` amb un informe i els esborranys per a Google Business Profile (si alguna cosa falla, obre una pull request).

## Anuncis (Meta i Google)

Les etiquetes de Meta (Pixel) i de Google (Google tag i la conversió de Google Ads) es configuren a dalt de `build.py`: `META_PIXEL_ID`, `GOOGLE_TAG_ID` i `GOOGLE_ADS_CONVERSION`. Mentre estiguin buides, la web no carrega cap etiqueta ni mostra l'avís de galetes. La versió de revisió (`index.html`) no en carrega mai.

- **Analítica (PostHog, a la UE)**: `POSTHOG_KEY` a `build.py`, el projecte «La Casa Vella» a eu.posthog.com. Es carrega a cada visita però no envia res fins que l'hoste tria: si accepta les galetes, tot (visites, clics, mapes de calor, rendiment, errors, enquestes i gravacions de la sessió amb tots els camps emmascarats, i el text marcat `data-private`); si les rebutja, només un recompte sense galetes. El formulari de targeta de Stripe no es grava mai. Cal tenir activat «Cookieless server hash mode» a la configuració del projecte.

- **Galetes**: amb alguna etiqueta configurada, la primera visita mostra un avís petit a la cantonada per acceptar-les o rebutjar-les. Fins que l'hoste no accepta no es carrega res. L'enllaç «Cookies» del peu torna a obrir l'avís; si les rebutja després d'haver-les acceptat, se n'esborren les galetes.
- **Esdeveniments**: `begin_checkout` / `InitiateCheckout` quan l'hoste tria un allotjament i passa a la pàgina de reserva (veu el preu), `add_payment_info` / `AddPaymentInfo` quan ha posat les dades i li surt el formulari de pagament, i `purchase` / `Purchase` (més la conversió de Google Ads) quan la reserva està pagada, amb l'import que diu Stripe (`/api/status`) i l'id de la sessió de Stripe com a número de comanda, perquè no es compti dues vegades. Si l'hoste encara no ha triat, s'esperen i s'envien si accepta. El `purchase` de PostHog l'envia el servidor quan Stripe confirma el pagament (`lib/analytics.js`, des de `stripe-webhook.js`), perquè compti encara que l'hoste no torni a la pàgina; la pàgina envia amb la reserva qui és el visitant a PostHog i d'on ve la visita (les `utm_`, `gclid`, `fbclid` i el referent de la primera pàgina), que queden a la sessió de Stripe.
- **Enllaços dels anuncis**: `?in=2026-11-13&out=2026-11-15` obre la web amb aquestes dates i la llista d'allotjaments lliures. Amb `&stay=montserrat` (o `la-pineda`, `les-vinyes`, `figarot`) va directament a la pàgina de reserva d'aquell allotjament, i `&guests=2` tria les persones. Afegeix-hi els `utm_source`, `utm_campaign`… que vulguis: Google els llegeix de l'adreça.

## Publicar a Cloudflare Pages

1. Cloudflare → Workers & Pages → Create → Pages → Connect to Git, i tria aquest repositori.
2. Build command: buit. Build output directory: `dist`.
3. Custom domains → afegeix el domini. Si el domini ja és a Cloudflare, el DNS i l'HTTPS es configuren sols.

Cada push a `main` publica la web de nou.

## Reserves (Stripe + Google Calendar)

El formulari calcula el preu (per defecte habitació 70 €, apartament 90 € la nit; 5 % de descompte per a 2 nits i 10 % a partir de 3; tot es canvia des de Maite) i obre el pagament de Stripe. Ho fan les funcions de `functions/api/` (Cloudflare Pages Functions), amb la lògica compartida a `lib/booking.js`:

- `quote`, `search`, `busy`: preu i disponibilitat (un allotjament o tots; nits ocupades per al calendari).
- `checkout`: comprova el calendari i obre el pagament de Stripe integrat a la pàgina de reserva. No bloqueja res fins que es paga.
- `stripe-webhook`: quan es completa el pagament, escriu la reserva al calendari de l'allotjament. Si mentrestant algú altre ha pagat les mateixes dates, retorna els diners.
- `release`: tanca la sessió de pagament si l'hoste canvia les dades o marxa.
- `status`: diu a la pàgina de tornada si el pagament s'ha completat.
- `settings`: preus, descomptes, normes i política de cancel·lació desats a Maite, perquè la pàgina mostri els actuals.

Cada allotjament té un Google Calendar a info@casavellarural.com, compartit amb un compte de servei de Google. Qualsevol esdeveniment al calendari d'un allotjament bloqueja aquelles nits, sigui quin sigui el títol (els marcats com a «Disponible» no). Per bloquejar dates a mà, n'hi ha prou amb crear-hi un esdeveniment.

Variables a Cloudflare Pages (Settings → Variables and secrets): `STRIPE_SECRET_KEY`, `STRIPE_PUBLISHABLE_KEY`, `STRIPE_WEBHOOK_SECRET`, `GOOGLE_SA_EMAIL`, `GOOGLE_SA_KEY`, `CAL_MONTSERRAT`, `CAL_LA_PINEDA`, `CAL_LES_VINYES`, `CAL_FIGAROT`, `CAL_RESTAURANT` (taules del restaurant), `SITE_URL`. Mentre no hi siguin, el formulari mostra el preu i remet al telèfon i al WhatsApp.

## Reserves del restaurant

El botó «Reservar taula» del restaurant obre `#taula`: l'hoste tria un dels dies oberts (cada un és un dia i una hora) i les persones, i deixa el nom, el correu, el telèfon i el que calgui tenir en compte. No hi ha pagament. Ho fa `functions/api/table.js`, amb la lògica a `lib/restaurant.js`:

- `GET /api/table?people=…`: els dies oberts que vénen i si n'hi ha lloc per a aquell grup.
- `POST /api/table`: torna a comprovar les places, escriu la taula al calendari del restaurant i envia la confirmació a l'hoste i un avís a la casa.

A la portada, sota el restaurant, surten els quatre pròxims dies oberts; tocant-ne un s'obre la reserva de taula amb aquell dia triat. El restaurant és tancat si no s'obre. A Maite (Restaurant, Dies oberts) s'hi afegeixen els dies que obre, cada un amb la seva hora (per exemple, el 31 de desembre a les 21:00). També hi ha les places de cada dia obert (per defecte, 15), el grup més gran que es pot reservar a la web (els més grans truquen) i les hores d'antelació. Es desa a KV amb la resta de normes. Sense cap dia obert, la pàgina ho diu i dona el telèfon.

El botó «Organitzar un esdeveniment» obre `#esdeveniment`, per a qui vol un dia que no és a la llista: l'hoste diu quantes persones (de 8 a 16) i què li agradaria, amb el nom, el correu i el telèfon. No porta dia. `functions/api/event.js` ho envia a info@casavellarural.com (respondre-hi li arriba a l'hoste) i l'hoste rep una còpia. No s'escriu al calendari: la casa li proposa dia, hora i menú. Sense la clau de Resend, la pàgina dona el telèfon.

Les taules es guarden en un Google Calendar propi del restaurant, compartit amb el mateix compte de servei, a la variable `CAL_RESTAURANT`. Mentre no hi sigui, la pàgina mostra les hores però remet al telèfon i al WhatsApp per reservar.

## Maite (back office)

Maite és el back office, a `maite.casavellarural.com`. Surt del mateix projecte de Cloudflare Pages: `functions/_middleware.js` mira el domini i, a `maite.`, serveix `dist/maite/` i les funcions de `functions/api/maite/` (amb la lògica a `lib/maite.js`). Des de qualsevol altre domini, aquestes rutes donen 404.

- **Calendari**: un mes amb una fila per allotjament. Es toca la primera nit i l'última per tancar dates o afegir una reserva. Tocant una reserva se'n veuen els detalls. L'última fila és el restaurant: l'hora de cada dia obert i les persones que hi ha apuntades; tocant un dia s'obre a Restaurant.
- **Reserves**: avui (qui arriba, qui hi és i qui marxa), properes, passades, cancel·lades i tancaments, amb cercador i un resum dels pròxims 30 dies.
- **Llista de cada reserva**: pagament (per a les de la web, el mètode que diu Stripe: targeta i últimes xifres, Apple Pay, transferència…, i el rebut; per a les directes, si està cobrada i com), correu, telèfon, documents d'identitat, registre de viatgers als Mossos, entrada i sortida (amb l'hora en què es marquen) i una nota interna. Les targetes de la llista diuen què falta.
- **Reserves directes** (telèfon, WhatsApp, en persona): s'escriuen al calendari de l'allotjament i bloquegen les nits a la web. Proposa el preu de la web, però es pot canviar.
- **Cancel·lar**: la reserva queda al calendari com a «CANCEL·LADA» i les nits queden lliures. Si es va pagar a la web, es pot retornar tot o una part per Stripe. Les que esperen la confirmació del banc no es poden cancel·lar fins que arriba.
- **Tancar dates**: un o més allotjaments, o tota la casa. Si alguna nit ja està ocupada, no es tanca res.
- **Preus**: un calendari per allotjament amb el preu de cada nit. A la dreta, el preu normal i, si es vol, un altre per a divendres i dissabte. Tocant un dia, o el primer i l'últim d'un període, s'hi posa un preu especial o una estada mínima per a qui arribi aquells dies, i es pot aplicar a la vegada a altres allotjaments. Hi ha tries ràpides per a tots els caps de setmana o tot el mes.
- **Descomptes**: per estada llarga, tants com calgui («a partir de 7 nits, un 15 % menys»). S'aplica el més alt.
- **Normes**: estada mínima i màxima, amb quanta antelació es pot reservar, hores d'entrada i sortida, i la política de cancel·lació (Flexible, Moderada, Estricta, No reemborsable o a mida). La web mostra la política al costat de les condicions, i cada reserva guarda la que va acceptar l'hoste: en cancel·lar-la, Maite proposa el retorn que toca.

- **Restaurant › Menús**: d'aquí surt tot el que té a veure amb un menú, com un esdeveniment. La pestanya mostra els menús fets (els dies, com va el post i les stories, «Envia per WhatsApp», «Edita») i «Nou menú», que obre el flux en tres passos: *Menú i dies* (el nom, els plats, les begudes, el preu i els dies, cada un amb la seva hora), *Post i stories* (la portada i les stories) i *Publica* (el copy i quan comença la promo). *Publica* diu què passarà en desar-lo: els dies que s'obren a la web, quan surt el post i quants recordatoris en farà Maite, comptats amb les mateixes regles que fa servir el pla (`menuReminders` i `capReminders` a `maite-app/src/social/catalog.ts`, que també fa servir `lib/plan.js`). En desar-lo, els dies s'obren a *Dies oberts* (els que ja hi eren no es tornen a obrir, i si en tanques un, no es recorda), la web mostra la imatge del menú a la reserva de taula fins a l'últim dia, i el post i les stories surten quan comença la promo (sense Instagram connectat es desen sense programar, i la promo compta igualment des d'aquell dia). Totes les stories del menú porten l'adhesiu d'enllaç a la reserva de taula amb el dia ja triat (`/?dia=2026-12-31T21:00#taula`). A *Dies oberts*, «Obre amb un menú» obre un menú nou amb aquell dia i aquella hora («Només obre el dia» l'obre sense menú), i cada dia obert diu de quin menú és i com va, amb «Obre el menú». Treure un menú no tanca els seus dies, per si ja hi ha taules. A *Publicar*, el llapis d'un post de menú porta aquí.
- **Restaurant**: les taules de cada dia obert, amb les places ocupades, i els pròxims dies amb taules. Es pot apuntar una taula (telèfon, WhatsApp, en persona), sense els límits de la web, canviar-ne una (el dia, l'hora, el nom, les persones, el contacte, la via i els comentaris, també des de *Cobrat*) i cancel·lar-ne una: queda al calendari com a «CANCEL·LADA» i les places tornen a quedar lliures (l'hoste no rep cap correu). A *Cobrat*: un calendari del mes amb el que s'ha cobrat cada dia i el total del mes; tocant un dia s'apunta el que ha pagat cada taula (es desa a l'esdeveniment de la taula), i avisa de les taules ja servides sense import. A *Dies oberts*: els dies que obre, cada un amb la seva hora, les places i si es pot reservar a la web amb els seus límits. Inici diu si el restaurant obre avui i amb quantes persones, i mostra els pròxims dies oberts amb les taules i les places.
- **Allotjaments**: tipus, nom, descripció, capacitat, característiques (amb icona) i fotos de cada allotjament, amb una vista prèvia de com es veu a la web. Les fotos es poden pujar (es redueixen al navegador i es guarden a R2), afegir de les que ja té la web, reordenar arrossegant-les o amb fletxes, i la primera és la portada. Les fotos pujades que ja no fa servir cap allotjament s'esborren. La capacitat compta per a la web, els pagaments i les reserves de Maite. El rètol amb el nom (`img/nom-*.png`) és una imatge i no canvia sol.
- **Xarxes socials › Pla**: Maite fa l'estratègia d'Instagram sola (`lib/plan.js`, decisions a `docs/social/estrategia.md`). Cada dilluns a partir de les 8:00 prepara la setmana següent i l'envia per correu a info@: 3 posts (dimarts i dijous a les 19:30, dissabte a les 10:30) i una story cada dia, cadascun amb el perquè. Què empeny surt de les reserves: l'allotjament amb nits lliures el cap de setmana que ve o entre setmana (la story porta l'enllaç a la pàgina de reserva amb aquelles dates), un dia de restaurant amb places, i si tot és ple, la casa i l'entorn. La foto de cada post i story la tria Maite, només entre les que tenen bona llum: la de la seva llista (l'habitació mateixa, el restaurant, la casa o l'entorn) que fa més temps que no surt, amb les preferides de la casa davant (tornen tres setmanes abans) i la resta de la sessió de novembre després, i mai la del dia abans. Les stories només fan servir fotos verticals (les apaïsades van als posts), tret de l'entorn, que no en té. Les preferides estan retocades amb la mateixa llum càlida, i sobre la foto el verd de la marca només puja on hi ha el text. Claude hi escriu el text de les imatges i els copies (sense la clau, els de les plantilles). Fins diumenge a les 23:59 es pot canviar, treure o aprovar; si ningú hi entra, surt tal com és. Si programes un post teu un dia que el pla ja en tenia un, el del pla es mou a un altre dia lliure d'aquella setmana (o es treu). Els menús fets a *Restaurant › Menús* tenen recordatoris propis, refets dos cops al dia a partir de les taules reservades: des de l'endemà que comença la promo, una story cada tres dies fins a la setmana abans de cada dia (cada dos si la sala és mig buida, amb un post deu dies abans); després, cada dos dies, cada dia els últims dies, el mateix dia, i cap quan és ple. Si la sala és mig buida, una story cada dia l'última setmana, dues al dia els últims tres dies, dues el mateix dia i un post quatre dies abans. Cada story porta a reservar el seu dia. Les stories porten l'adhesiu d'enllaç, que l'API d'Instagram no deixa posar: les penja soles amb l'enllaç el mateix Cloudflare (`lib/igapp.js`, pas 10), que parla amb Instagram com l'app del mòbil amb la sessió del compte. Mentre el robot no hi és, a l'hora toca, el correu del matí ho recorda, i «Penja amb l'enllaç» (a l'app obre Instagram amb la story i l'enllaç copiat) i «Ja l'he penjada». Si ni el robot ni tu l'heu penjada en 3 hores (es canvia a *Com planifica*), Maite la publica sola sense enllaç; si Instagram ja té una story teva d'aquella hora, només la marca com a penjada. Les imatges del pla les dibuixa el servidor (pas 9); sense, les dibuixa Maite quan s'obre (web o app). Tot és a la graella com qualsevol altre post: surt a *Calendari* (ara també les stories) i a *Publicar*.
- **Restaurant › Menús, la llista**: cada menú fet té «Envia per WhatsApp»: obre WhatsApp amb la portada i el text del menú (plats, preu i l'enllaç per reservar taula) per enviar-lo a la llista de difusió (WhatsApp no deixa enviar-hi des d'un programa). Queda apuntat quan s'ha enviat. L'app d'Android avisa amb una notificació quan toca enviar-lo (mitja hora després que surti i dos dies abans de l'últim dia) i quan hi ha una story per penjar a mà; tocant-la s'obre Maite a la pestanya. Els avisos els calcula l'app cada vegada que s'obre (`data/Reminders.kt`) i no surten del mòbil.
- **Menú**: *Normes* és una pestanya d'*Allotjaments* i *Correus* una de *Xarxes socials*; els enllaços antics (`#/rules`, `#/emails`) obren aquestes pestanyes.
- **Analítica**: dues pestanyes. *Pèrdues i guanys*: els ingressos surten sempre de Maite (els calendaris de reserves, per nit, i el restaurant de *Cobrat*), mai del full; el benefici brut és els ingressos menys les despeses directes (les categories del full de restaurant, cuina, menjar, begudes, compres, neteja, bugaderia, amenities, allotjament i comissions, `DIRECT` a `lib/pnl.js`); després hi ha les altres despeses (programari, anuncis i la resta) i el resultat. *Anuncis*: la inversió per canal (Meta i Google, de la categoria Ads del full, i el compte d'anuncis de Meta si el full no els porta), amb les reserves pagades a la web del període, el que van pagar i la inversió per reserva. Les pèrdues i guanys d'un període (setmana passada, aquest mes, mes passat, aquest any, o les dates que triïs a *Dates*). Cada línia s'obre: els allotjaments en cada allotjament (nits i ocupació) i les seves reserves, el restaurant en cada dia de servei, i cada categoria de despeses en els seus apunts; si el període té més d'un mes, a sota hi ha el mes a mes. Hi surten els ingressos (allotjaments per nit, restaurant pel que diu *Cobrat*), les despeses per categoria i el benefici brut, abans d'impostos (`lib/pnl.js`). Les despeses surten d'un full de Google que porta la casa: es connecta enganxant-ne l'enllaç a Analítica (es desa al KV, clau `expenses`; o la variable `EXPENSES_SHEET`). La primera pestanya ha de tenir les columnes Data, Concepte, Categoria i Import (també en castellà o anglès, en qualsevol ordre; si hi ha una columna Tipus, les files «Ingrés» que són una devolució resten de la seva categoria, i els altres ingressos del full no compten, perquè els ingressos surten de les reserves i de *Cobrat*), i el full s'ha de compartir amb el compte de servei (`GOOGLE_SA_EMAIL`) o ser de l'usuari de `GOOGLE_DRIVE_AS`. Es llegeix per Drive (la primera pestanya, exportada en CSV), la mateixa API que fan servir els documents, així que no cal activar l'API de Sheets. Els anuncis de Meta s'hi sumen sols des del compte d'anuncis (amb `META_ADS_TOKEN`), tret que el full ja els porti (un concepte amb «Meta Ads»): llavors només compten els del full. El resum del dilluns porta el mateix de la setmana passada i el mes fins ara.
- **Pregunta**: una conversa amb Claude sobre la casa (`lib/chat.js`). Respon a partir de les reserves, les taules, els preus, Instagram i les pèrdues i guanys, i quan convé canviar alguna cosa ho proposa: un preu o una estada mínima per a unes nits (es fa amb el botó, com a Preus) o una pàgina de Maite per obrir. No canvia res sense el botó. Per enviar-te on es fa una cosa, el botó obre la pestanya exacta (i el dia, el menú o la reserva quan n'hi ha): per exemple *Xarxes socials › Publicar* per desprogramar una story. La conversa i les anteriors (*Converses anteriors*, les últimes 30) es queden al dispositiu; *Conversa nova* guarda la d'ara a la llista. Fa servir Claude Opus 5.5 amb esforç baix; cal la clau de Claude (pas 7).
- **Xarxes socials**: les plantilles d'Instagram amb la marca, en pestanyes. *Posts* (1080 × 1350) i *Stories i reels* (1080 × 1920): cada plantilla té variacions («Una altra opció»), s'hi pot posar una foto pròpia i es descarrega en PNG a mida real. Cada plantilla es pot editar (el llapis): el text que hi canviïs és el de les publicacions que en facis a partir d'aleshores. *Generador de posts*: un post nou, «Des d'una plantilla» o «Genera amb IA». «Des d'una plantilla»: tries la plantilla, la variació, la foto i el text, amb la vista prèvia al costat, hi escrius el copy (Claude en proposa, o la biblioteca; sense copy no s'afegeix) i l'afegeixes al perfil («Crea'n un post» a cada plantilla de *Posts* hi porta). En afegir o confirmar un post, s'obre «Publica a Instagram»: ara, programat per a un dia i una hora o més endavant; la targeta mostra després com està i porta a *Publicar* o al *Calendari*. «Genera amb IA»: es fa un post o una story descrivint-lo («el sopar de Cap d'Any, 31 de desembre, 65 € per persona»), amb una foto pròpia o sense. Es tria de què va (menú, habitació, apartament, restaurant, entorn o general) i, dins seu, la plantilla, o es deixa que ho triï Claude. Sense foto, Claude tria una foto de la casa; amb foto, la mira, la posa en una plantilla que en té i n'escriu a partir del que s'hi veu (llavors la descripció és opcional). En tots dos casos escriu el text de la imatge i el copy, i en proposa dues opcions. L'anunci del restaurant pot anar sol o com a carrusel amb el menú darrere (*Una imatge* o *Carrusel*), també a les plantilles; quan Claude el fa i li has donat els plats, també omple el menú. Cada proposta es pot editar abans de confirmar-la (el text de la imatge, la foto i el copy), descarregar, copiar-ne el copy o confirmar per a la graella amb el copy ja desat (cal la clau de Claude, pas 7). Els menús es fan a *Restaurant › Menús* (més amunt). Les stories no van a la graella. Les portades dels destacats encara són a `templates.ts`, però sense pestanya. *Publicar*: com es veurà el perfil amb els posts confirmats (en pantalla ample, la vista del perfil es desplaça per dins quan els publicats la fan més alta que la finestra); s'ordenen triant el número de cadascun (l'1 és el primer que es publica), es treuen, es descarreguen d'un en un o tota la graella (`01-detall.png`, `02-…`), cada post que no s'ha publicat es pot editar (variació, foto i text; si està programat, se'n puja la imatge nova), i cada post té el seu copy: Claude en proposa tres en català (Instagram tradueix els posts a qui llegeix en una altra llengua), i es pot editar; «Biblioteca» hi posa els copies de la casa. *Calendari*: només per mirar el pla: el dia de cada post programat, en un mes, i el que ja hi ha publicat a Instagram cada dia (des de Maite o des de l'app, amb l'enllaç al post); es programa des de *Publicar*. A *Publicar*, cada post té «Programa» i «Publica ara»: es programa per a un dia i una hora, i els programats passen davant, per ordre de dia; la imatge es puja en programar-lo i es publica sola, amb el copy que tingui llavors (cal el Worker de `cron/`; mentrestant, es publica quan algú obre Xarxes socials després de l'hora). A *Publicar*, la graella també s'ordena arrossegant els posts; els programats hi porten el dia i l'hora, i a sota hi ha el que ja és a Instagram, amb una marca i l'enllaç al post. Els publicats es veuen també a «Publicats». Les plantilles són a `maite-app/src/social/` (`templates.ts` es genera des del disseny) i les seves fotos a `maite-app/public/social/`.

Tot això s'aplica de seguida a la web i als pagaments. Les reserves fetes a Maite no segueixen les normes (es pot reservar per telèfon el mateix dia o una sola nit).

Tot el que hi ha al calendari continua sent la referència: el que es crea a mà a Google Calendar també surt a Maite (en blau) i bloqueja les nits.

| --- | --- | --- |

| El pla d'Instagram: com planifica i les setmanes fetes i aprovades (els seus posts són a `social`, amb el camp `auto`) | Cloudflare KV, espai `MAITE` (clau `plan`) | Maite i el Worker de `cron/` |

No hi ha cap altra base de dades: tot el que es canvia a Maite es llegeix al moment des de la web.

### Posar-lo en marxa

1. **Domini**: Cloudflare Pages → el projecte → Custom domains → afegeix `maite.casavellarural.com`.
2. **Accés amb Google**: a Google Cloud Console crea un client OAuth («Web application») amb l'URI de redirecció `https://<equip>.cloudflareaccess.com/cdn-cgi/access/callback`. A Cloudflare Zero Trust → Settings → Authentication → Login methods → Add new → Google, enganxa-hi l'ID i el secret del client. Després, Access → Applications → Add an application → Self-hosted, amb el domini `maite.casavellarural.com`, només el mètode Google i una política *Allow* amb els correus que hi poden entrar. Copia l'**Application Audience (AUD) tag**.
3. **Preus i normes**: Workers & Pages → KV → crea un espai de noms (per exemple `casavella-maite`). Al projecte de Pages → Settings → Bindings → KV namespace, amb el nom de variable `MAITE`.
4. **Variables** (Settings → Variables and secrets): `ACCESS_TEAM` (el nom de l'equip de Zero Trust, el que va davant de `.cloudflareaccess.com`) i `ACCESS_AUD` (el tag del pas 2). Les de Stripe i Google Calendar són les mateixes de la web.
5. **Fotos**: R2 → crea un bucket (per exemple `casavella-fotos`). Al projecte de Pages → Settings → Bindings → R2 bucket, amb el nom de variable `PHOTOS`. Sense això, Maite deixa triar entre les fotos de la web però no pujar-ne de noves.
6. **Documents dels hostes a Google Drive**: a Google Cloud, activa la Google Drive API al mateix projecte del compte de servei del calendari. Després tria una de les dues opcions:
   - **Unitat compartida** (més senzill): posa la carpeta «05.01 Documentació checkin» dins d'una unitat compartida i afegeix-hi el correu del compte de servei (`GOOGLE_SA_EMAIL`) com a *Gestor de contingut*.
   - **La teva unitat**: a la consola d'administració de Google Workspace → Seguretat → Controls d'API → Delegació a tot el domini, afegeix l'ID de client del compte de servei amb l'àmbit `https://www.googleapis.com/auth/drive`, i posa la variable `GOOGLE_DRIVE_AS` amb el correu del propietari de la carpeta (per exemple `info@casavellarural.com`).

   En tots dos casos, posa la variable `DOCS_FOLDER` amb l'ID de la carpeta (el tros de l'URL després de `/folders/`). Cada reserva hi té una carpeta numerada, «05.01.07 - Nom (20/10/2026 - 23/10/2026)», que es crea quan s'hi puja el primer document. Un compte de servei no pot desar fitxers a «La meva unitat» d'una altra persona sense una d'aquestes dues opcions.

7. **Copies amb Claude** (Xarxes socials): posa el secret `ANTHROPIC_API_KEY` amb una clau de l'API d'Anthropic (console.anthropic.com). Sense ella, Maite proposa els copies de la casa (els de «Biblioteca»). Els copies tenen un to romàntic, inspirat en Mas d'en Bruno, Off Grid, Oller del Mas i Son Brull, i només porten «Reserva per DM» quan el post és d'alguna cosa concreta (un menú, una data, un cap de setmana). L'opció triada es pot editar abans de desar-la. Fa servir Claude Haiku 5.5, el model més barat: cada vegada que es demanen tres opcions costa uns 0,0005 $ (mil peticions, uns 50 cèntims), i les opcions ja escrites es guarden mentre la pàgina és oberta. Fer un post o una story a partir d'una descripció envia a Claude totes les plantilles i les fotos, i costa unes quantes vegades més (encara menys d'un cèntim).
8. **Publicar a Instagram** (Xarxes socials):
   1. Al mòbil, passa el compte d'Instagram a professional (Configuració → Tipus de compte → Empresa o Creador).
   2. A [developers.facebook.com](https://developers.facebook.com) crea una app de tipus *Business* i afegeix-hi el producte **Instagram** amb «API setup with Instagram login». No cal pàgina de Facebook ni revisió de Meta: l'app només publica al teu compte.
   3. A «Generate access tokens», afegeix el compte d'Instagram, accepta els permisos `instagram_business_basic` i `instagram_business_content_publish` (i `instagram_business_manage_insights` perquè l'equip de xarxes vegi l'abast, els desats i els compartits de cada post, a `/api/social-stats`), i copia el testimoni.
   4. Posa'l com a secret `INSTAGRAM_TOKEN` a Cloudflare Pages (Production). Maite el renova cada setmana sol (dura 60 dies) i desa el renovat a KV (clau `instagram`). Si mai caduca, n'hi ha prou amb generar-ne un de nou i canviar el secret.

   Cada post de la graella té el botó de publicar: Maite en fa un JPEG (un per imatge, si és un carrusel), el desa a R2 i Instagram l'agafa de `SITE_URL/photos/…` amb el copy desat. Les stories de *Menús* es publiquen igual, sense copy. Sense el secret, el botó no surt.
   5. Per programar posts: secret `SOCIAL_CRON_SECRET` a Cloudflare Pages i el Worker de `cron/` en marxa amb el mateix secret (`cron/README.md`). El mateix Worker fa anar el pla de cada setmana; mentre no hi sigui, el pla avança quan s'obre *Xarxes socials › Pla*.
9. **Imatges del pla al servidor** (perquè el pla surti encara que ningú obri Maite): Cloudflare → Manage account → Account API tokens → Create token → Custom, amb el permís *Account › Browser Rendering › Edit*. A Cloudflare Pages, el secret `CF_RENDER_TOKEN` amb el testimoni i la variable `CF_ACCOUNT_ID` amb l'ID del compte (a la dreta de la pàgina Workers & Pages). El navegador de Cloudflare obre `/render/render.html` (la plantilla a mida real, `maite-app/src/render.ts`, construïda a `dist/render/`) i el JPEG va a R2 com qualsevol foto. Uns quinze dibuixos a la setmana, dins del gratuït (10 minuts al dia).
10. **Stories amb l'adhesiu d'enllaç, soles** (`lib/igapp.js`): no és l'API oficial d'Instagram, sinó la de l'app del mòbil, i va contra les seves condicions: Instagram pot demanar verificar el compte o, en el pitjor cas, limitar-lo. Fa servir la sessió del compte, no la contrasenya:
    1. En un ordinador, entra a instagram.com amb el compte de La Casa Vella.
    2. Obre les eines del navegador (Chrome: F12, o clic dret › Inspecciona) › Application › Cookies › `https://www.instagram.com` i copia el valor de `sessionid` (comença amb números).
    3. A Cloudflare Pages, secret `IG_SESSIONID` amb aquest valor, i torna a desplegar. No tanquis la sessió d'aquell navegador (fer «Tanca la sessió» la invalida).

    A *Xarxes socials › Pla* surt «Les stories surten soles amb l'enllaç» i el compte. Si Instagram la deixa de acceptar (dura mesos), Pla ho diu i les stories surten sense enllaç fins que la tornes a copiar. Una alternativa que corre a casa, amb usuari i contrasenya: `story-bot/` (`story-bot/README.md`, amb el secret `STORY_BOT_SECRET`).
11. **Avisos a l'app d'Android** (Firebase Cloud Messaging): els mòbils amb l'app reben un avís quan es paga una reserva a la web, quan es puja el primer document d'una reserva, quan es reserva una taula o es demana un esdeveniment a la web, i quan es cancel·la una reserva o una taula a Maite. Cada dia a partir de les 10:00, si alguna taula d'ahir no té l'import apuntat a *Cobrat*, «Taules per cobrar», que obre *Cobrat* aquell dia (`lib/weekly.js`). Qui ho fa a Maite no rep l'avís del que acaba de fer. En tocar-lo, l'app obre la reserva o el restaurant aquell dia.
   1. A [console.firebase.google.com](https://console.firebase.google.com) crea un projecte (o afegeix Firebase al projecte de Google Cloud que ja hi ha).
   2. Configuració del projecte → General → Les teves apps → Afegeix una app d'Android amb el paquet `com.casavellarural.maite`. Baixa `google-services.json` només per llegir-hi quatre valors (no va al repositori, l'app els agafa en compilar): `mobilesdk_app_id` per a `MAITE_FCM_APP_ID`, `current_key` per a `MAITE_FCM_API_KEY`, `project_id` per a `MAITE_FCM_PROJECT_ID` i `project_number` per a `MAITE_FCM_SENDER_ID`. Es posen com a variables d'entorn en fer la versió de l'app (`android/README.md`).
   3. Pestanya Cloud Messaging: comprova que la **Firebase Cloud Messaging API (V1)** està activada (si no, l'enllaç porta a activar-la a Google Cloud).
   4. Pestanya Comptes de servei → Genera una clau privada nova. Baixa un JSON: enganxa'l sencer com a secret `FCM_SERVICE_ACCOUNT` a Cloudflare Pages (Production).

   Sense el secret, el servidor no envia res. Sense les quatre variables, l'app es compila i funciona igual, sense avisos. Android 13 o posterior demana permís per als avisos una vegada, després d'entrar; si es diu que no, es canvia a Configuració → Aplicacions → Maite → Notificacions.

Cada crida de Maite comprova el testimoni de Cloudflare Access, de manera que sense els passos 2 i 4 no s'hi pot entrar. Sense el pas 3, Maite funciona però no deixa desar preus ni normes, i la web fa servir els valors per defecte de `lib/booking.js`.
